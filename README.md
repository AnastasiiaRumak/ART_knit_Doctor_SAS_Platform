# ArtKnit — Система автоматической маршрутизации пациентов

> **Хакатон «Не потерять пациента»** от СМ-Клиники.
> Превращаем текст протокола УЗИ в управляемый клинический маршрут.

## 🎯 Что делает

Протокол УЗИ (текст) → Парсинг → Триггер → Специалист → Маршрут → HTML-экран


1. **Читает** протокол УЗИ — любой текст, любые формулировки.
2. **Извлекает** клинически значимые триггеры (полип эндометрия, ДГПЖ, BI-RADS 3–5, TI-RADS, стенозы и т.д.).
3. **Проверяет отрицания** — `не выявлено`, `в норме` → триггер не срабатывает.
4. **Определяет специалиста** — по матрице маршрутизации из таблиц СМ-Клиники.
5. **Строит маршрут** — с учётом приоритетов и спорных ситуаций.
6. **Генерирует HTML** — экран врача, экран пациента, дашборд руководителя.

## 🚀 Быстрый старт

### Требования

- **Python 3.11+**
- **GNU Make** (Linux/macOS: `sudo apt install make`)
- **Bash** или **Zsh**

### Установка и запуск (полный цикл)

```bash
# 1. Клонировать репозиторий
git clone <repo-url>
cd sm_clinic_routing

# 2. Полный цикл: setup + parse + test + demo + manager
make all

# 3. Открыть 3 ключевых экрана
make open-all

Всё. После make all:

✅ Установлены зависимости

✅ Пересобраны YAML-конфиги

✅ Прогнаны 89 протоколов (метрики в output/metrics_report.json)

✅ Сгенерированы 9 экранов врача + 9 экранов пациента

✅ Построен дашборд руководителя


Отдельные команды

make setup          # Установка (venv + зависимости)
make parse          # Пересобрать YAML из таблиц
make test-real      # Прогнать 89 реальных протоколов
make test           # Unit-тесты (pytest)
make demo           # Сгенерировать 9 HTML
make manager        # Построить дашборд
make open-doctor    # Открыть экран врача (Кардио, urgent)
make open-patient   # Открыть экран пациента (ЩЖ)
make open-manager   # Открыть дашборд
make open-all       # Все 3 ключевых экрана
make audit          # Журнал аудита (последние 5 записей)
make metrics        # Метрики (JSON)
make format         # Форматировать код (black + ruff)
make lint           # Проверить код (ruff)
make valgrind       # Проверить память (tracemalloc)
make coverage       # Покрытие тестами (pytest-cov)
make profile        # Профилирование узких мест

### Оптимизация

| Слой | Что ускорено | Эффект |
|---|---|---|
| **ConfigLoader** | Предкомпиляция **989 regex** при загрузке | Убрано **52 192** вызова `re.escape` |
| **Preprocessor** | Предкомпиляция **84 keyword-regex** | **2.75×** ускорение |
| **Extractor** | Использование готовых regex | **2×** ускорение |
| **Cache `.docx`** | Сохранение текста в `.txt` | **20×** для повторных прогонов |
| **Итого** | **~3× общее ускорение** | 1319 мс → **470 мс** на протокол |

## 🔍 Объяснимость (Explainability)

Для **каждого триггера** система показывает **цитату из протокола** и **применённое правило**.

### Что видит врач

**Экран врача:**

Приоритетная находка
✅ легочная гипертензия
👨‍⚕️ Кардиолог 👨‍⚕️ Пульмонолог ⏰ Ускоренно

Цитата: «Легочная гипертензия, СДЛА 42 мм рт.ст.»

Почему такой маршрут?

Найден признак: легочная гипертензия

Источник: Эхокардиография от 26.08.2026

Специалист: Кардиолог + Пульмонолог

Приоритет: ⏰ Ускоренно · до 7 дней

Сценарий: мультидисциплинарный

### Журнал аудита

**`output/routes_audit.jsonl`** — для каждого протокола:
```json
{
  "patient_id": "1030",
  "patient_name": "Орлова Елена Петровна",
  "finding": "легочная гипертензия",
  "finding_id": "cardio_legochnaya_gipertenziya",
  "specialist": ["Кардиолог", "Пульмонолог"],
  "urgency": "urgent",
  "deadline_days": 7,
  "scenario": "мультидисциплинарный",
  "multidisciplinary": true,
  "basis": "Эхокардиография от 26.08.2026",
  "reason": "легочная гипертензия — консультация кардиолог, пульмонолог",
  "quote": "Легочная гипертензия, СДЛА 42 мм рт.ст.",
  "status": "assigned",
  "status_label": "⏰ Требуется ускоренное решение",
  "organ_codes": ["cardio"]
}

Соответствие ТЗ (пункт 14):

✅ «кто» — patient_id, patient_name

✅ «что» — finding, specialist, urgency

✅ «когда» — timestamp

✅ «на каком основании» — basis, reason, quote, finding_id

🛡️ Безопасность
Решение не подменяет врача.

Принцип	Реализация
❌ Не ставит диагноз	Только триггер + цитата
❌ Не назначает лечение	Только рекомендация консультации
✅ Только рекомендует	«Рекомендована консультация профильного специалиста»
✅ Экстренные находки	Эскалация персоналу (emergency), не SMS
✅ Онконастороженность	Мягкий сценарий (врач-координатор звонит лично)
✅ Минимум информации в SMS	Нейтральные тексты, без диагнозов
✅ Защита от переспама	Максимум 5 напоминаний (24ч, 72ч, 7д, 14д, 30д)
✅ Никаких реальных ПДн	Только обезличенные протоколы
Сценарии коммуникации
Urgency	Сценарий	Канал
emergency	Срочный контакт	Звонок координатора
oncological	Мягкий сценарий	Врач-координатор лично
urgent	Стандартный	Push + SMS + ЛК
planned	Стандартный	Push + SMS + ЛК
observation	Мягкий	Только ЛК

🔧 Расширяемость

Все правила — в YAML. Чтобы добавить новый триггер:

Шаг 1. Откройте нужный YAML
bash
nano config/triggers/thyroid.yaml
Шаг 2. Допишите триггер
yaml
  - id: thyroid_novyy_priznak
    synonyms: [новый признак, синоним1, синоним2]
    specialist: [Эндокринолог]
    urgency: planned
    source: Новый признак
    regex: (?i)(новый\s+признак|синоним1|синоним2)
Шаг 3. Перезапустите
bash
make parse      # пересобрать YAML
make demo       # сгенерировать HTML
Код менять не надо. Система автоматически подхватит новый триггер.

Что можно настроить без кода
Что	Где
Новые синонимы	config/triggers/*.yaml
Новые RegEx	config/triggers/*.yaml (поле regex)
Числовые пороги	config/sizes.yaml
Отрицания	config/negations.yaml
Спорные ситуации	config/disputes.yaml
Приоритеты и сроки	config/priorities.yaml
Тексты сообщений	templates/*.j2
